# AST Pocket：記述別の根拠不足・改訂候補の優先確認（第2版）

## 何を自動化したか

GPC clustersとMSSA菌血症の公開済み8章草案について、`scripts/triage-evidence-gaps.mjs` が**臨床上の判断に影響しそうなキーワードを含む箇条書き**を検出し、既存の`docs/evidence/sab-2026-10-21.json`の短いアンカーと紐付くかを確認します。

2026-10-21の実データによるテスト結果：

| 確認対象 | 件数 |
| --- | ---: |
| 注目キーワードを含む草案の箇条書き | 52 |
| 同一箇条書き内に台帳アンカーのあるもの | 14 |
| 根拠アンカーのないもの | **38** |

**意味**：残る38件の記述について、原典の対応関係を記録する作業が優先されます。14件についても、文全体が医学的に承認されたわけではありません。キーワードに該当しなかった文章は数に入らず、この数字が本文すべての件数や医学的な検証率を示すものではありません。

重複度や医学的な意味の評価はしません。各候補について、原典本文の該当節・版・発行日を人が確認し、安全に差分化する必要があります。

## 実際の学習履歴から確認票へ

`scripts/build-weekly-review-pack.mjs` は、mainの`content/index.json`に実在するWeeklyの「今週の重要ポイント」から、日付・番号を**明示指定**して入力を作ります。

- 内容を新しく生成するのではなく、学習ポイントの原文とSHA-256を保持して出所を追跡します。
- 既存のdraftノートと関連する表現を提示しますが、**意味の重複や医学的な妥当性は判定しません**。
- どのGLが対応するかを勝手に割り振らず、`guideline_source_assigned: false`のままにします。
- 出力はgit管理対象外の`local-intake/`であり、既存ノート／臨床Knowledgeを更新しません。
- 公開GitHubに含まれる元のWeeklyであっても、改訂ノートに追加する際の安全性・医学的なレビューは別に必要です。

実際の登録済みの2026年10月9日Weeklyから、1番の「S. aureus菌血症 → 再血培」を用いて動作をテストしました。確認票の例は [2026-10-09 MSSA改訂確認票](../review-drafts/weekly-2026-10-09-mssa-revision-proposal.md) にあります。

### 使い方（ローカル・追加API不要）

```bash
node scripts/triage-evidence-gaps.mjs

mkdir -p local-intake
node scripts/build-weekly-review-pack.mjs \
  --date 2026-10-09 \
  --point 1 \
  --topic infection-mssa-bacteremia \
  --chapter diagnosis \
  --out local-intake/mssa-2026-10-09-review.md
```

過去24時間のChatGPT全会話はこれでは取得できません。**公開Weeklyが存在するときのみ**、その記録を起点にレビュー候補を組み立てます。深夜3時の取得失敗と学習0件の区別は別の監査が担います。

## 今後の展開

1. 38件のアンカー未登録箇条書きのうち、治療選択・再血培・期間・心エコーなど臨床リスクの高い事項から原典を紐付けて精査する。
2. 人が承認した要点を詳細ノートへの差分案にし、医療情報の最終確認を待つドラフトPRを作る。
3. ChatGPTの03:00タスクが取得できた実データからWeeklyが作成された場合に、同じ確認票作成へ接続する。会話が取得できない時はデータを捏造しない。
4. 今回の静的テスト・テキスト類似性チェックは、医学的な意味検証や最終承認を代替しない。
