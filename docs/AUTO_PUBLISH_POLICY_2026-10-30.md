# AST Pocket 自動公開運用（2026-10-30 改訂）

## 方針：学習モードは原則「事前の個別承認なし・検証後自動公開」

利用者の明示的な指示により、これまでの「すべてユーザー承認までPRで停止」を終了する。毎朝3:00 JSTのChatGPTタスクが実際に取得できた、公開可能な一般化済みの感染症学習情報は、**利用者に毎回承認を求めず**追加を進める。

**ただし、公開GitHubではドラフトブランチ/PRも公開される。患者・職員・施設固有情報、診療録、認証情報、会話全文、私的URL等はPR作成前から取り込まない。疑いがあれば取り込みそのものを中止する。**

### 自動公開の対象

- 取得日時と取得範囲が説明できる新規学習のWeekly。重複なしで `content/index.json` に登録する。
- 学習モードのみの出典付き教科書草案、スペクトル解説、練習用資料の追加（既存機能や旧データを壊さない変更に限る）。
- 公式情報源を確認した週次情報（本人の会話学習ログとは明確に別管理）。
- 既に公開ブランチで承認待ちの上記資料。差分・公開安全・競合・テストを検証してから段階的に統合する。

### 自動公開の条件（全て必須）

1. 内容の公開安全性を**書き込み前**に確認。正規表現等の機械検査だけでは不十分。
2. 出典URL・日付・照合範囲を明記。部分照合と全文確認を区別し、裏付けできない主張は断定しない。
3. **医学的未承認の学習資料はdraft／原典確認待ちとして表示**する。医学的verifiedと自称しない。
4. 変更差分が学習モードの範囲に限定され、矛盾・重複・既存データ消失がない。
5. GitHub Actions `Validate AST Pocket` が**成功**。CI失敗/未確認なら自動マージ禁止。
6. マージ後にPages公開状態を確認。確認できない場合は「公開未確認」と報告し、成功とみなさない。

### 自動公開しない項目

- 臨床モードの診療推奨、抗菌薬選択、投与量、投与期間、承認済みKnowledgeの改訂。
- 既存の復習問題の正答変更、医学的verifiedへの変更。
- 根拠不十分・相反する資料、患者安全に直結する重要な改訂。
- 大幅なコード改修、データ削除、機能破壊、CI失敗、プライバシー上の疑い。

これらは「要確認」として留保する。**「公開承認不要」は「医学的正当性を無審査で承認する」ことではない。**

### 定期タスクと監査

- 毎朝3:00 JSTの既存タスクは継続。OpenAI APIは使わない。
- ChatGPT全会話の完全自動収集は現状保証できない。収集成功・0件・検索失敗とアクセス可能範囲を必ず区別。
- 新規学習が0件なら空ファイルを作らない。
- 成果報告に「追加件数、重複、保留、PR/commit、CI、mainマージ、Pages公開確認」を明記。実際に実行できなかった場合は理由を明記。
- 既存の安全上の検証仕様 `docs/DAILY_CHAT_INGEST_V1.md` などは維持する。本書の「条件を満たす学習モードなら事前の個別承認を不要とする」点が運用変更である。
